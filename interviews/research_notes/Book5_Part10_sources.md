## Verification
All 177 examples in all 40 prompts are rendered from the same data (scratch/B5P10_wavea/qs.py, generated from draft.py by gen.py with expected values produced by refs.py) that scratch/B5P10_wavea/check_examples.py executes with `python3 -I`: ALL OK on the final run (about 7 s). Each reference solution is cross-checked against an independent brute force or plain recursion on 400 seeded random small inputs (15612 checks in all). Findings from the runs: memoised recursions at the quoted sizes (climbing stairs 5000, house robber 10^5, coin change 10^4, perfect squares 10^4, combination sum IV 2000, coin change II 5000, paint fence 10^5, cooldown stock 5000) raise RecursionError at the default limit 1000, and the 3-step stair recursion fails at n = 1000, 1500 and 2000 and passes at 500 (informational: the prompt only uses n <= 500 and n >= 2000); the upward-loop 0/1 knapsack equals the unbounded answer on 1000 of 1000 and differs from the true 0/1 answer on 722; in combination sum IV the ordered count differs from the unordered count on 140 of 600 and the swapped loop order always yields the unordered count; the plain parent-pointer rebuild of coin change differs from the lexicographic tie rule on 19 of 800; bisect_left used for the non-decreasing LIS gives the strict length and is wrong on 363 of 600; ascending-height tie-break is wrong for Russian dolls on 224 of 600; the naive circular formula max(Kadane, total - min) is wrong on 363 small lists, all of them all-negative; the maximum-subarray tie rule matches the O(n^2) enumeration on all 19530 lists of length <= 6 with values -2..2; the jump-game reachable set is a prefix on all 5460 lists of length <= 6 with values 0..3; the k >= n // 2 shortcut equals the full at-most-k table on 600 random inputs. Another bug found and fixed on the way: the first cooldown oracle blocked the buy on the day after the cooldown day (it gave 2 instead of 3 for [1, 2, 3, 0, 2]); the cooldown oracle now models the cooldown day exactly.
