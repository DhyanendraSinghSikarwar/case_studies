# Chapter 11: Flowcharts and Decision Trees

**What you will learn:** how to turn a written rule or process into a flowchart or decision tree, read one step by step, and check that every path ends properly.

## Concept in plain language

### What is a flowchart?

A flowchart is a picture of a process. Boxes say what to do, diamonds ask a question, and arrows show the order. You start at Start, follow the arrows, and stop at an End. Anyone who follows the same arrows with the same facts must reach the same result. That is the whole point: a process written in a paragraph can be read in two ways, but a flowchart cannot.

### The five shapes

| Shape | Name | What it holds | Exits |
|---|---|---|---|
| Oval | Start / End | The first step, or a final result | Start has 1 exit; End has none |
| Rectangle | Action (process) | Something you do or calculate: 'add 1 to tries' | Exactly 1 |
| Diamond | Decision (question) | A question with a yes/no answer | One arrow for each answer, each labelled |
| Parallelogram | Input / output | Data coming in or going out (optional; we use rectangles) | Exactly 1 |
| Arrow | Flow line | The order of the steps | Points one way |

### Flowchart versus decision tree

- A **flowchart** may go back to an earlier step. Going back is called a **loop** (for example 'ask for the password again').
- A **decision tree** is a flowchart that only branches forward: it starts at one question, each answer leads to the next question, and every branch ends in an outcome (called a **leaf**). No loops.
- Many business rules ('who gets a bonus') are decision trees. Processes that retry or repeat ('try the payment up to 3 times') need a loop.

### Four building blocks

| Block | What it looks like | Example in words |
|---|---|---|
| Sequence | Box, then box, then box | Pack the order, then print the label |
| Choice | One diamond, two exits | 'Is the customer a member?' |
| Chain of choices | Diamonds one after another | 'Within 7 days?' then 'Unused?' (both must be yes) |
| Loop | An arrow that goes back to an earlier box | 'Ask for the password again' |

### How to draw a flowchart from text (five steps)

1. **Underline the questions and the actions.** Questions have 'if', 'when', 'more than', 'at least'. Actions are things done.
2. **List every possible result.** Each result becomes an End box. Several arrows may point to the same End.
3. **Put the questions in order.** If one check can end the process early (such as 'no stock'), it goes first.
4. **Draw it.** Start, then the first question; label every arrow leaving a diamond; connect each branch to an action or an End.
5. **Test it.** Run a few cases, including the exact boundary values (the number in the rule itself). Check that every path reaches an End and no diamond has an unlabelled or missing exit.

### How flowcharts are written in this book

We cannot show pictures here, so every flowchart is written as a text outline. Each step has a short ID (S for Start, D1, D2 for decisions, P1 for actions, E1, E2 for ends). Read it from top to bottom:

- `(Start)` and `(End)` are the oval shapes.
- `[Action]` is a rectangle.
- A line that starts with `->` continues the arrow from the box just above it.
- `<Question>` is a diamond; the indented lines under it are its labelled exits (`Yes:` and `No:`).
- `continue at X (shown above)` means the arrow goes to a box already written; on paper you would draw the arrow to that box.

When you answer a practice question, draw it on paper with real shapes, or write the same kind of outline. Both are fine. Then trace your test cases, writing the IDs of the boxes you visit.

### Edge values and wording

| Words in the rule | Test to use | Does the boundary number take the Yes arrow? |
|---|---|---|
| 'at least 999', '999 or more' | total >= 999 | Yes |
| 'more than 500' | amount > 500 | No (500 is not more than 500) |
| 'within 7 days', '7 days or fewer' | days <= 7 | Yes |
| 'less than 60' | score < 60 | No (60 is not less than 60) |

> **Why this matters for data work:** Analysts turn business rules into IF formulas, CASE WHEN statements and data-cleaning checks. Drawing the rule first shows missing cases and boundary mistakes before any formula is written, and it gives you a picture to show a manager when you confirm that you understood the rule.

## 5 solved examples

### Example 1: Payslip delivery (one question)

**Process in words:** If an employee has an email address, send the payslip by email. Otherwise print it.

**Step 1: find the question.** 'Does the employee have an email address?' This is the only decision, so there will be one diamond. *Why:* every 'if' in the text becomes a diamond.

**Step 2: find the results.** 'Send payslip by email' and 'Print payslip'. *Why:* each result is an End.

**Step 3: draw it.**

```text
   ( Start )
       |
       v
< Has email address? >--Yes--> [ Send payslip by email ] --> ( End )
       |
       No
       v
[ Print payslip ] --> ( End )
```

In our outline form:

```text
S (Start) Start
-> D1 <Question> Does the employee have an email address?
    Yes: E1 (End) Send payslip by email
    No: E2 (End) Print payslip
```

**Step 4: test.** *Why:* a chart is only trustworthy once you have run it.

| Input | Path through the chart | Result |
|---|---|---|
| has an email | `S > D1(Yes) > E1` | Send payslip by email |
| no email | `S > D1(No) > E2` | Print payslip |

### Example 2: Student discount (two questions, both must be yes)

**Process in words:** A shop gives 20% off to students who show a valid student ID. Everyone else pays the full price.

**Step 1: spot the 'and'.** The discount needs two things at once: being a student and showing an ID. *Why:* 'and' means a chain of two diamonds where a No at either one leaves the process through the 'no discount' exit.

**Step 2: order the questions.** Ask 'Is the customer a student?' first. *Why:* if the answer is No there is no point asking about an ID.

**Step 3: draw it.** Notice that two arrows point to the same End box ('No discount'); that is allowed.

```text
S (Start) Start
-> D1 <Question> Is the customer a student?
    Yes: D2 <Question> Is a valid student ID shown?
        Yes: E1 (End) Give 20% discount
        No: E2 (End) No discount
    No: continue at E2 (shown above)
```

**Step 4: test all four combinations.** *Why:* with two yes/no questions there are only four cases, so we can check every one.

| Input | Path through the chart | Result |
|---|---|---|
| student, ID shown | `S > D1(Yes) > D2(Yes) > E1` | Give 20% discount |
| student, no ID | `S > D1(Yes) > D2(No) > E2` | No discount |
| not a student, ID shown | `S > D1(No) > E2` | No discount |
| not a student, no ID | `S > D1(No) > E2` | No discount |

### Example 3: Shipping fee by weight (three outcomes from two questions)

**Process in words:** Parcels of 1 kg or less cost 40 to ship. Parcels over 1 kg and up to 5 kg cost 90. Heavier parcels cost 180.

**Step 1: count the outcomes.** Three fees, so three End boxes. *Why:* a diamond has two exits, so three outcomes need two diamonds one after another.

**Step 2: ask the smallest band first.** 'Is the weight 1 kg or less?' Yes leads to 40. *Why:* once you pass this question you already know the weight is above 1 kg, so the next question can simply say '5 kg or less' without repeating 'more than 1'.

**Step 3: second question.** 'Is the weight 5 kg or less?' Yes leads to 90, No leads to 180.

```text
S (Start) Start
-> D1 <Question> Is the weight 1 kg or less?
    Yes: E1 (End) Fee is 40
    No: D2 <Question> Is the weight 5 kg or less?
        Yes: E2 (End) Fee is 90
        No: E3 (End) Fee is 180
```

**Step 4: test the edges** (1, 1.01, 5, 5.5).

| Input | Path through the chart | Result |
|---|---|---|
| 0.5 kg | `S > D1(Yes) > E1` | Fee is 40 |
| 1 kg | `S > D1(Yes) > E1` | Fee is 40 |
| 1.01 kg | `S > D1(No) > D2(Yes) > E2` | Fee is 90 |
| 5 kg | `S > D1(No) > D2(Yes) > E2` | Fee is 90 |
| 5.5 kg | `S > D1(No) > D2(No) > E3` | Fee is 180 |

### Example 4: Weekly sales target (a loop)

**Process in words:** A shop has 4 days to reach a sales target of 500. Add each day's sales to a running total. As soon as the total reaches 500 the target is reached. If all 4 days are added and the total is still below 500, the target is missed.

**Step 1: find what repeats.** 'Add the next day's sales' happens again and again. *Why:* repeated work is a loop: an arrow goes back to the same action box.

**Step 2: set up before the loop.** 'Set total = 0 and day = 0' sits before the loop. *Why:* if the setting-up were inside the loop, the total would reset to 0 each round.

**Step 3: two exits from the loop.** After each addition ask 'Is total 500 or more?' (Yes: done, target reached). If No, ask 'Have all 4 days been added?' (Yes: target missed; No: go back and add the next day). *Why:* a loop needs a way out in both directions, success and running out of days. Without the second question the chart would never stop.

```text
S (Start) Start
-> P0 [Action] Set total = 0 and day = 0
-> P1 [Action] Add the next day's sales to total; add 1 to day
-> D1 <Question> Is total 500 or more?
    Yes: E1 (End) Target reached
    No: D2 <Question> Have all 4 days been added?
        Yes: E2 (End) Target missed
        No: continue at P1 (shown above)
```

**Step 4: trace two cases.** Daily sales 120, 180, 260, 90 and then 100, 100, 100, 100. Illustrative numbers.

| Daily sales | Path through the chart | Result |
|---|---|---|
| 120, 180, 260, 90 | `S > P0 > P1 > D1(No) > D2(No) > P1 > D1(No) > D2(No) > P1 > D1(Yes) > E1` | Target reached |
| 100, 100, 100, 100 | `S > P0 > P1 > D1(No) > D2(No) > P1 > D1(No) > D2(No) > P1 > D1(No) > D2(No) > P1 > D1(No) > D2(Yes) > E2` | Target missed |

In the first case the totals after each pass are 120, 300 and 560, so the chart ends on the third pass. In the second case the totals are 100, 200, 300 and 400, and the fourth pass finds that all 4 days are used, so the target is missed.

### Example 5: Probation review (a decision tree)

**Process in words:** A rating of 4 or 5 confirms the employee. A rating of exactly 3 extends the probation if attendance is 90% or more; otherwise the employee is not confirmed. A rating of 1 or 2 means not confirmed.

**Step 1: list the leaves.** Three outcomes: Confirm, Extend probation, Do not confirm. *Why:* the leaves tell you how many distinct End boxes you need; 'Do not confirm' will be reached from two places.

**Step 2: pick the first split.** Rating splits the group three ways (4 or 5, exactly 3, 1 or 2). Ask 'Is the rating 4 or 5?' then 'Is it exactly 3?'. *Why:* attendance matters only for rating 3, so it is asked at the end of that one branch and nowhere else.

```text
S (Start) Start
-> D1 <Question> Is the rating 4 or 5?
    Yes: E1 (End) Confirm
    No: D2 <Question> Is the rating exactly 3?
        Yes: D3 <Question> Is attendance 90% or more?
            Yes: E2 (End) Extend probation
            No: E3 (End) Do not confirm
        No: continue at E3 (shown above)
```

As a tree drawing (the same chart, laid out as branches):

```text
Rating 4 or 5?
|-- Yes: Confirm
|-- No: Rating exactly 3?
      |-- No: Do not confirm
      |-- Yes: Attendance 90% or more?
            |-- Yes: Extend probation
            |-- No: Do not confirm
```

**Step 3: test the edges.** *Why:* attendance 89 versus 90 is the boundary.

| Input | Path through the chart | Result |
|---|---|---|
| rating 4, attendance 80 | `S > D1(Yes) > E1` | Confirm |
| rating 3, attendance 90 | `S > D1(No) > D2(Yes) > D3(Yes) > E2` | Extend probation |
| rating 3, attendance 89 | `S > D1(No) > D2(Yes) > D3(No) > E3` | Do not confirm |
| rating 2, attendance 95 | `S > D1(No) > D2(No) > E3` | Do not confirm |

## 2 real-life scenarios

### Scenario 1 (commerce): the return desk

**Illustrative policy.** Electronics can be returned within 10 days of delivery; every other item within 30 days. A return inside the window gets a full refund if the packaging is intact, or an 80% refund if it is not. A return outside the window gets no refund.

The first question 'Is the item electronics?' only sets the window (an action on each branch), then both branches join at the same question about days. This shows that actions can sit on a branch and that branches can join again.

```text
S (Start) Start
-> D1 <Question> Is the item electronics?
    Yes: P1 [Action] Set window = 10 days
    -> D2 <Question> Are days since delivery within the window?
        Yes: D3 <Question> Is the packaging intact?
            Yes: E2 (End) Full refund
            No: E3 (End) Partial refund (80%)
        No: E1 (End) Refund not allowed
    No: P2 [Action] Set window = 30 days
    -> continue at D2 (shown above)
```

Four orders, traced (all numbers illustrative):

| Input | Path through the chart | Result |
|---|---|---|
| electronics, 8 days, packaging intact | `S > D1(Yes) > P1 > D2(Yes) > D3(Yes) > E2` | Full refund |
| clothing, 25 days, packaging opened | `S > D1(No) > P2 > D2(Yes) > D3(No) > E3` | Partial refund (80%) |
| electronics, 12 days, intact | `S > D1(Yes) > P1 > D2(No) > E1` | Refund not allowed |
| clothing, 31 days, intact | `S > D1(No) > P2 > D2(No) > E1` | Refund not allowed |

**What to notice:** the same 12 days is too late for electronics but fine for clothing. A flowchart makes that difference obvious, where a paragraph often hides it.

### Scenario 2 (data): checking rows in an HR upload

**Illustrative rule.** Before loading rows of an employee file: a row with no employee ID is rejected; a row with a joining year after 2026 or a salary of 0 or less is sent to a person for review; everything else is accepted.

```text
S (Start) Start
-> D1 <Question> Is the employee ID present?
    Yes: D2 <Question> Is the joining year 2026 or earlier?
        Yes: D3 <Question> Is the salary above 0?
            Yes: E3 (End) Accept row
            No: E2 (End) Send to review
        No: continue at E2 (shown above)
    No: E1 (End) Reject row
```

Four rows, traced (invented data):

| Input | Path through the chart | Result |
|---|---|---|
| ID present, joined 2024, salary 52000 | `S > D1(Yes) > D2(Yes) > D3(Yes) > E3` | Accept row |
| no ID, joined 2024, salary 48000 | `S > D1(No) > E1` | Reject row |
| ID present, joined 2027, salary 50000 | `S > D1(Yes) > D2(No) > E2` | Send to review |
| ID present, joined 2023, salary 0 | `S > D1(Yes) > D2(Yes) > D3(No) > E2` | Send to review |

**What to notice:** both 'review' rules lead to the same End, which is why the 'send to review' box has two arrows pointing at it. This is exactly how data-cleaning checks are planned before they are written as formulas or queries.

## Mistake log

1. **Unlabelled arrows out of a diamond.** Every exit of a question must say Yes or No (or the answer it stands for).
2. **Boundary slips.** Using 'more than' when the rule says 'at least' sends the boundary value down the wrong arrow. Always test the exact number in the rule.
3. **A loop with no exit, or a counter reset inside the loop.** Set counters before the loop; give the loop an exit for both success and running out of tries.
4. **Wrong order of questions.** A check that can end the process early (no stock, balance too low, no record) belongs first.
5. **Dead ends.** A box with no outgoing arrow that is not an End. Walk every path to an End before you call the chart finished.

## Recap

- A flowchart shows a process with ovals (Start and End), rectangles (actions), diamonds (questions) and arrows.
- Every diamond has one labelled arrow for each answer; three outcomes need two diamonds in a row.
- A decision tree only branches forward; a loop sends an arrow back and needs a counter and an exit.
- Draw by underlining questions and actions, listing results, ordering the checks, then drawing.
- Always test the boundary values and make sure every path reaches an End.
