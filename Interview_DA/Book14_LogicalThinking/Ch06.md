## Concept in plain language

### Quick refresher

An **argument** is a set of statements where some, called **premises**, are offered as reasons for another, called the **conclusion** (Chapter 1). This chapter asks two separate questions about an argument:

1. Does the **logic** work? (validity)
2. Are the **facts** right? (soundness)

### Valid and invalid

An argument is **valid** if the conclusion **must** be true whenever all the premises are true. There is no way to make the premises true and the conclusion false.

An argument is **invalid** if it is *possible* for all the premises to be true and the conclusion still false.

Key points a beginner often misses:

- Validity is about the **shape** (the form) of the reasoning, not about whether the statements are true in the real world.
- A valid argument can have **false** premises and a **false** conclusion.
- An invalid argument can have **true** premises and even a **true** conclusion; it just did not earn it.

### Sound and unsound

An argument is **sound** if it is **valid** and **all its premises are actually true**. Then the conclusion is guaranteed true.

An argument is **unsound** if it is invalid, **or** valid with at least one false premise.

| | All premises true | At least one premise false |
|---|---|---|
| **Valid** | **Sound**: conclusion is true | Valid but unsound: conclusion may be true or false |
| **Invalid** | Unsound: conclusion may be true or false | Unsound: conclusion may be true or false |

Only one box guarantees a true conclusion: valid with all true premises.

### The counterexample method (your main tool)

To show an argument is **invalid**, build a small situation where every premise is true and the conclusion is false. That situation is a **counterexample**. One is enough.

To suspect an argument is **valid**, you try hard to build such a situation and fail every time. (For simple shapes below, a table of all cases proves it.)

### Four if-then shapes to memorise

Using P and Q for two statements:

| Shape | Form | Verdict |
|---|---|---|
| Affirm the condition (modus ponens) | If P then Q. P. So Q. | **Valid** |
| Deny the result (modus tollens) | If P then Q. Not Q. So not P. | **Valid** |
| Affirm the result | If P then Q. Q. So P. | **Invalid** (Q may have other causes) |
| Deny the condition | If P then Q. Not P. So not Q. | **Invalid** (Q may happen anyway) |

Two more valid shapes and one invalid twin:

| Shape | Form | Verdict |
|---|---|---|
| Chain | If P then Q. If Q then R. So if P then R. | **Valid** |
| Either-or, rule one out | P or Q. Not P. So Q. | **Valid** |
| Either-or, wrongly rule out | P or Q. P. So not Q. | **Invalid** ("or" may allow both) |

### Quantifier shapes (a short preview)

- All A are B. x is A. So x is B. **Valid.**
- All A are B. x is B. So x is A. **Invalid** (B may be bigger than A).
- Some A are B. Some B are C. So some A are C. **Invalid** (the "some" groups may not overlap).

Syllogisms get a whole chapter later (Chapter 12).

## Why this matters for data work

> Reports, proposals and dashboards are arguments: the data are the premises and the recommendation is the conclusion. Separating "is the reasoning valid?" from "are the inputs true?" tells you whether to fix the logic or to fix the data.

## 5 solved examples

### Example 1: Valid and sound

"If an employee has a pending leave request, the manager gets a notification. Mohan has a pending leave request (this is a fact on the system). So Mohan's manager gets a notification."

1. Shape: If P then Q; P; so Q. **Why:** matching the shape tells you the verdict.
2. The shape is modus ponens, which is **valid**.
3. Are the premises true? Suppose the system rule and the pending request are both confirmed. Then both are true.
4. Valid and all premises true: **sound**. The conclusion is guaranteed.

### Example 2: Valid but unsound

"All data analysts know SQL. Meera is a data analyst. So Meera knows SQL."

1. Shape: All A are B; x is A; so x is B. **Valid.**
2. Check premise 1: is it really true that every analyst knows SQL? Not necessarily; this is an overgeneralisation. We cannot call it true.
3. If premise 1 is false, the argument is **valid but unsound**, and its conclusion is not guaranteed (Meera may or may not know SQL).
4. **Why this matters:** the logic is fine, so the fix is on the fact side: check whether Meera knows SQL directly.

### Example 3: Invalid (affirming the result)

"If the sales campaign ran, sales rose. Sales rose. So the campaign ran."

1. Shape: If P then Q; Q; so P. This is the invalid "affirm the result" shape.
2. Build a counterexample: P = campaign ran, Q = sales rose. We need P false, Q true, and both premises true.
3. Scenario: there was no campaign, but it was festival season and sales rose anyway. Premise 1 is not broken (the campaign did not run, so there is nothing to break). Premise 2 is true. Conclusion false.
4. One counterexample: **invalid**. Rising sales have other possible causes.

Truth-table view: of the four combinations of (P, Q), the row P false, Q true makes both premises true and the conclusion false.

| P | Q | If P then Q | Q | P (conclusion) |
|---|---|---|---|---|
| T | T | T | T | T |
| T | F | F | F | T |
| **F** | **T** | **T** | **T** | **F** |
| F | F | T | F | F |

The third row is the counterexample.

### Example 4: Invalid even if the conclusion happens to be true

"Some interns are in Pune. Some Pune staff are in HR. So some interns are in HR."

1. Shape: Some A are B; some B are C; so some A are C. Invalid shape.
2. Counterexample: two people only. Meera is an intern in Pune working in Finance. Nikhil is a Pune employee in HR who is not an intern.
3. Premise 1: some interns are in Pune (Meera). True. Premise 2: some Pune staff are in HR (Nikhil). True. Conclusion: some interns are in HR. False (Meera is in Finance).
4. **Why this matters:** even if the real company happened to have an intern in HR, the argument would still be invalid, because the premises did not guarantee it.

### Example 5: Chain and either-or

"If a candidate passes screening, they get an interview. If they get an interview, they are shortlisted. So if a candidate passes screening, they are shortlisted."

1. Shape: If P then Q; if Q then R; so if P then R. **Valid** (the chain).
2. Now flip the conclusion: "So if a candidate is shortlisted, they passed screening." That is invalid. Counterexample: a referred candidate who skipped screening but was shortlisted. All premises hold, conclusion fails.
3. Now an either-or: "The error is in the data entry or in the formula. It is not in the data entry. So it is in the formula." Valid (rule one out).
4. But "The error is in the data entry or the formula. It is in the data entry. So it is not in the formula." is invalid: both could be wrong at once.

## 2 real-life scenarios

All numbers are **illustrative**.

### Scenario 1: A business proposal with a hidden flaw (commerce)

A proposal says: "Every branch that introduced a loyalty card saw repeat customers rise. Our new branch will introduce a loyalty card. So our new branch will see repeat customers rise."

- Logic: All A are B; x is A; so x is B. **Valid.**
- Facts: the first premise says "every" branch. If the company only checked, say, 4 branches (illustrative) it cannot support "every". One branch where repeat customers did not rise makes the premise false.
- Verdict: valid, **soundness not established**. Your useful question is "Which branches did you check?", not "Is the logic right?"

### Scenario 2: A dashboard check (data)

An analyst argues: "If the report is correct, the monthly totals match the ledger. The monthly totals match the ledger (both show 4,800 units, illustrative). So the report is correct."

- Shape: If P then Q; Q; so P. **Invalid.**
- Counterexample: two mistakes that cancel each other (one product over-counted by 50, another under-counted by 50) leave the total at 4,800 while the report is wrong.
- Matching totals is a good sign, but not a guarantee. Next step: compare totals per product, not only overall.

## Mistake log

1. **Mixing up valid and true.** A valid argument is about structure; truth of the statements is a separate check.
2. **Thinking a true conclusion makes an argument valid.** An invalid argument can land on a true conclusion by luck.
3. **Falling for the two invalid if-then shapes.** "If P then Q, Q, so P" and "If P then Q, not P, so not Q" feel natural, and both fail.
4. **Treating "or" as "exactly one".** In logic "or" usually allows both, so ruling out the second after the first is true is invalid.
5. **Calling an argument sound without checking the premises.** Sound needs valid structure and every premise actually true.

## Recap

1. Valid means the conclusion must be true if the premises are; it is about structure, not about real-world truth.
2. Sound means valid and every premise actually true; only then is the conclusion guaranteed.
3. To prove an argument invalid, give one counterexample: true premises, false conclusion.
4. If P then Q, with P is valid; with not Q is valid; with Q or with not P is invalid.
5. Check the logic first and the facts second, then fix whichever side is broken.
