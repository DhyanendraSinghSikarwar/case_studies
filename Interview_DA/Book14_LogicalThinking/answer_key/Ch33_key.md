# Chapter 33 answer key: Estimation (Fermi Problems)

All inputs are illustrative assumptions given in the questions. Results were recomputed by code.

## Self-check answers

1. 300 x 220 = 66,000 teas a year. (People x teas per person per day x days.)
2. Fix what is counted (cups sold, not made at home; stalls only or cafes too) and the place and time window (one city, one day). Also state the population assumption.
3. The paths differ by 400,000 / 50,000 = 8 times, far more than ordinary rounding. At least one assumption is wrong or a unit is mixed up. Compare the factors in each path, find the one that seems least believable, fix it, and recompute.

## Practice answers

**Q1.** Pages: 600 x 8 x 220 = 1,056,000. Reams: 1,056,000 / 500 = 2,112. Sanity: about 1 million pages for 600 people is about 1,760 pages per person a year, or 8 a day, which matches the input. About 1.06 million pages, about 2,100 reams.

**Q2.** Hours: 7.5 x 365 x 70 = 191,625 hours. Years: 191,625 / 8,760 (hours in a year, 24 x 365) = 21.875, about 22 years. Share: 7.5 / 24 = 31.25%, nearly a third. Sanity: a third of 70 is about 23, consistent.

**Q3.** Loaves: 120 x 6 x 50 = 36,000. Flour: 36,000 x 0.4 = 14,400 kg. Sanity: 14,400 kg is 14.4 tonnes, plausible for a year of daily baking at this scale.

**Q4.** Leave days: 250 x 1.5 x 12 = 4,500. Working days: 250 x 230 = 57,500. Share: 4,500 / 57,500 = 7.83%, about 8%. Sanity: 1.5 days a month is 18 a year, 18/230 = 7.8%, same answer through a per-person route.

**Q5.** 9 x 180 x 26 = 42,120. Per day: 9 x 180 = 1,620; 1,620 x 26 = 42,120. About 42,000 a month (gross takings, before costs).

**Q6.** Visits: 300 x 365 x 10 = 1,095,000. Claim 5,000,000 / 1,095,000 = 4.57, about 4.6 times too high. Even counting every visit (repeat visits included), the claim is not believable unless the shop was much busier than assumed.

**Q7.** 80 x 2 x 12 x 22 = 42,240 minutes. 42,240 / 60 = 704 hours. Sanity: 704 hours / 80 people = 8.8 hours each a month, about 24 minutes a day, matches 2 x 12.

**Q8.** Overall conversion: 0.20 x 0.25 x 0.80 = 0.04. Applications needed: 90 / 0.04 = 2,250. Check forward: 2,250 x 0.20 = 450 shortlisted; x 0.25 = 112.5 offers; x 0.80 = 90 hires. So about 2,250 applications.

**Q9.** Users in the rush: 600 / 2 = 300. One lift in 30 minutes does 30 / 2 = 15 round trips x 8 = 120 people. Lifts: 300 / 120 = 2.5, round up to 3 (you cannot have half a lift). Sanity: 3 lifts move 360, which is more than 300.

**Q10.** Cells: 3,000,000 x 15 = 45,000,000. Bytes: 45,000,000 x 10 = 450,000,000, which is 450 MB. Files: 3,000,000 / 1,048,576 = 2.86, round up to 3 files. Sanity: 3 files x 1,048,576 = 3,145,728, which covers 3,000,000.

**Q11.** Ordinary: 60 / 4 = 15 per hour x 8 = 120. Peak: 60 / 2 = 30 per hour x 2 = 60. Total 180 customers. Revenue 180 x 340 = 61,200. Sanity: 61,200 / 10 hours = 6,120 an hour.

**Q12.** Path A: 2,000,000 x 0.30 x 2 = 1,200,000. Path B: 2,000,000 / 500 = 4,000 stalls; 4,000 x 250 = 1,000,000. Ratio 1.2, well inside a factor of 2. Report about 1.0 to 1.2 million, best single number about 1.1 million.

**Q13.** Total checking: 1,200 x 3 = 3,600 minutes = 60 hours. Capacity: 2 x 6 = 12 hours a day. Days: 60 / 12 = 5 working days.

**Q14.** Low: 60 x 365 = 21,900. High: 100 x 365 = 36,500. Middle (80 a day): 80 x 365 = 29,200. Ratio high/low = 36,500 / 21,900 = 1.67. A range of 22,000 to 36,500 is a reasonable statement.

**Q15.** Central: 1,000 x 0.3 x 4 = 1,200. Lowest: 800 x 0.1 x 3 = 240. Highest: 1,200 x 0.5 x 5 = 3,000. Spread of each factor (high / low): A 1,200/800 = 1.5; B 0.5/0.1 = 5; C 5/3 = 1.67. B has the widest spread, so it drives the uncertainty; the overall high/low ratio is 3,000 / 240 = 12.5 (and 1.5 x 5 x 1.67 = 12.5). Improve B first (better data or a second path).

**Q16.** Active households: 1,000,000 x 0.20 = 200,000. Orders a day: 200,000 / 5 = 40,000. Peak orders: 40,000 x 0.55 = 22,000 over 4 hours = 5,500 an hour. Riders at peak: 5,500 / 2.5 = 2,200. Sanity: 2,200 riders x 2.5 = 5,500 an hour, matches. Note the hourly peak (5,500) is about twice the average over a 14-hour day (40,000 / 14 = 2,857, an extra assumption), which is why peak, not average, sets staffing.

**Q17.** Bytes per hour: 40,000 x 250 = 10,000,000 = 10 MB. Per day: 10 x 24 = 240 MB. Days: 50,000 / 240 = 208.3, about 208 days (roughly 7 months). Sanity: 208 days x 240 MB = 49,920 MB.

**Q18.** Leavers: 2,400 x 0.14 = 336. Cost: 336 x 300,000 = 100,800,000. One point lower is 1% of 2,400 = 24 fewer leavers; saving 24 x 300,000 = 7,200,000. The 300,000 per leaver is an exercise assumption, not a fact.

**Q19.** Maximum from registered users: 30,000 x 5 = 150,000. Remainder: 2,000,000 - 150,000 = 1,850,000, which is 1,850,000 / 2,000,000 = 92.5% of visits. So at least 92.5% must come from non-registered visitors (or automated traffic), or the report is wrong.

**Q20.** Meeting time: 10 x 1 x 800 x 48 = 384,000. Prep: 10 x 0.5 x 800 x 48 = 192,000. Total 576,000. New: meeting 8 x 0.75 x 800 x 48 = 230,400; prep 8 x 0.5 x 800 x 48 = 153,600; total 384,000. Saving 576,000 - 384,000 = 192,000 a year.
