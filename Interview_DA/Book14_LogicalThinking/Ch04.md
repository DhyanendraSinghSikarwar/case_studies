# Chapter 4: If-Then, Converse, Inverse, Contrapositive and If and Only If

**What you will learn:** how to read and write "if-then" rules, which reversals of a rule are safe and which are traps, and how to test a rule against real cases.

## Concept in plain language

### The if-then rule (a conditional)

An **if-then rule** says: whenever the first thing happens, the second thing must follow. We write it "If p then q".

- **p** (the part after "if") is the **condition**. Textbooks call it the hypothesis or antecedent.
- **q** (the part after "then") is the **result**. Textbooks call it the conclusion or consequent.

Example: "If a shipment is delayed (p), the customer gets an apology email (q)."

Think of it as a **promise**. When is a promise broken? Only when the condition happened and the result did not.

| p (condition) | q (result) | Is the rule "If p then q" true? | Why |
|---|---|---|---|
| T | T | True | promise kept |
| T | F | **False** | promise broken |
| F | T | True | promise says nothing about this case |
| F | F | True | promise says nothing about this case |

This surprises many beginners: if the shipment is **not** delayed, the rule cannot be broken, whether or not an email is sent. (Logicians call a rule that is true only because its condition never happened "vacuously true".) A rule is only **broken** by one case: condition true, result false. That one case is called a **counterexample**.

### The three relatives

Start from "If p then q" and change it in three ways. Use the delayed-shipment rule as the running example.

| Name | How to build it | Example |
|---|---|---|
| **Original** | If p then q | If a shipment is delayed, the customer gets an apology email. |
| **Converse** | swap: If q then p | If the customer gets an apology email, the shipment was delayed. |
| **Inverse** | negate both: If NOT p then NOT q | If a shipment is not delayed, the customer does not get an apology email. |
| **Contrapositive** | swap and negate both: If NOT q then NOT p | If the customer does not get an apology email, the shipment was not delayed. |

The key facts (you will see the proof in the solved examples):

- **The original and its contrapositive always mean the same.** If one is true, so is the other.
- **The converse and the inverse always mean the same as each other**, but **not** the same as the original. The original can be true while they are false.

So the only safe reversal is the contrapositive (swap AND negate). Swapping alone gives the converse, negating alone gives the inverse; both are traps.

### If and only if

"p if and only if q" (short form: **iff**) means the rule works in **both** directions: "If p then q" **and** "If q then p". It is true when p and q are both true or both false, and false when they differ. Example: "A coupon works if and only if the cart total is at least 500" (illustrative): a cart of 520 must get the coupon, and a cart of 450 must not.

### Everyday wordings and what they mean

| Wording | Means | Direction to remember |
|---|---|---|
| p if q | If q then p | the "if" part is the condition |
| p only if q | If p then q | "only if" points to what is required |
| p unless q | If NOT q then p | "unless" works like "if not" |
| p provided that q | If q then p | same as "if" |
| every / all A are B | If it is an A, it is a B | a rule about a group |

"Only if" is the most reversed phrase in logic. "You may enter only if you have a pass" means: **if you entered, you had a pass.** It does **not** mean everyone with a pass entered.

> **Why this matters for data work**
> Data rules ("if an order is above the limit, it needs approval") are if-then rules. Auditing means hunting for the one counterexample. And mixing up a rule with its converse is how people wrongly claim that something causes something else.

## 5 solved examples

### Example 1: all four versions side by side

**Rule:** "If a shipment is delayed (p), the customer gets an apology email (q)."

1. Write the three relatives as in the table above. (Why: each one changes the rule in a different, exact way.)
2. Test all four against every combination of p and q. (Why: if two statements give the same answer in every combination, they are equivalent.)

| p (delayed) | q (email) | Original: if p then q | Converse: if q then p | Inverse: if NOT p then NOT q | Contrapositive: if NOT q then NOT p |
|---|---|---|---|---|---|
| T | T | T | T | T | T |
| T | F | **F** | T | T | **F** |
| F | T | T | **F** | **F** | T |
| F | F | T | T | T | T |

**Reading:**
- Original and contrapositive give the same column (T, F, T, T): **equivalent**.
- Converse and inverse give the same column (T, T, F, T): **equivalent to each other**, but different from the original.
- Row 3 (not delayed, but an email was sent, perhaps a courtesy message) breaks the converse and inverse while the original stays true. The original never promised "no email without a delay".

### Example 2: a wrong reversal, and the counterexample that exposes it

**Rule:** "If an employee is in the Payroll team, she can open salary files." Is the converse "If an employee can open salary files, she is in the Payroll team" also true?

1. Remember: a rule is false if you can find one case where the condition holds and the result fails. (Why: that is the only way a rule breaks.)
2. For the converse, the condition is "can open salary files" and the result is "is in Payroll". Look for someone who can open salary files but is not in Payroll: for example, an internal auditor given access. (Why: this is the counterexample.)
3. The auditor does **not** break the original rule (she is not in Payroll, so the promise says nothing about her).

**Conclusion:** the original can be true while its converse is false. One counterexample is enough to reject the converse.

### Example 3: "only if"

**Statement:** "A visitor enters the building only if she has a pass."

1. "Only if" points to what is required. The requirement is the pass. (Why: "only if" names a necessary thing.)
2. So the rule is: **If the visitor enters, then she has a pass.** (Why: entering without a pass is the case that would break it.)
3. Test: Rina has a pass but waits in the cafe and never enters. Is the rule broken? No: the rule never said that having a pass forces entry.

**Conclusion:** "enters only if has a pass" is the same as "if enters then has a pass". It is **not** "if has a pass then enters".

### Example 4: "unless"

**Statement:** "The team goes on the trip unless the budget is cut."

1. Read "unless" as "if not". (Why: the trip happens in the ordinary case; the budget cut is the exception.)
2. Rule: **If the budget is not cut, then the team goes.**
3. Test: the budget is cut. Does the rule tell us whether the team goes? No. The condition ("budget not cut") is false, so the promise is silent; the team may or may not go.

**Conclusion:** "p unless q" gives a guarantee only when q does not happen. (In everyday talk people sometimes mean "and if q happens, p does not"; when it matters, ask. In this book we use the plain reading above.)

### Example 5: if and only if

**Rule (illustrative):** "A coupon works if and only if the cart total is at least 500."

1. Split it into two rules. (Why: iff means both directions.)
   - If the coupon works, then the total is at least 500.
   - If the total is at least 500, then the coupon works.
2. Test four carts.

| Cart | Total | Coupon worked? | Total at least 500? | Does the iff rule hold? |
|---|---|---|---|---|
| 1 | 650 | Yes | T | Yes (both true) |
| 2 | 450 | No | F | Yes (both false) |
| 3 | 520 | No | T | **No** (total qualifies but the coupon did not work) |
| 4 | 300 | Yes | F | **No** (coupon worked on a small cart) |

**Conclusion:** iff holds only when both sides have the same truth value. Cart 3 breaks the "if total at least 500 then coupon works" half; cart 4 breaks the "if coupon works then total at least 500" half.

## 2 real-life scenarios

Numbers are invented and labelled illustrative.

### Scenario 1: Auditing an approval rule (commerce and data)

Rule (illustrative): "If an order is above 10,000, it needs a second approval." An analyst checks six orders:

| Order | Amount | Above 10,000? | Second approval? | Rule broken? |
|---|---|---|---|---|
| 1 | 12,000 | T | Yes | No |
| 2 | 8,500 | F | No | No |
| 3 | 15,500 | T | No | **Yes** |
| 4 | 10,000 | F (exactly 10,000 is not above) | No | No |
| 5 | 22,000 | T | Yes | No |
| 6 | 9,000 | F | Yes | No |

Only order 3 is a counterexample. Order 6 has a second approval without needing one: that does not break the rule (it would break the converse "if second approval then above 10,000", which nobody promised). Order 4 shows why reading "above" carefully matters.

### Scenario 2: The Monday salary (daily life and HR)

Rule (illustrative): "If you submit your timesheet by Friday, you are paid on Monday."

- Ravi **was paid on Monday**. Can we say he submitted by Friday? **No.** That is the converse. Payroll may have paid him for another reason.
- Meena **was not paid on Monday**. Can we say she did not submit by Friday? **Yes.** That is the contrapositive: if she had submitted, she would have been paid.
- Tara **did not submit by Friday**. Can we say she is not paid on Monday? **No.** That is the inverse; the rule is silent about her.

So from the result alone you can only reason safely when the result is **missing**.

## Mistake log

1. **Assuming the converse** ("The rule says delayed shipments get an email, so an email means a delay"). Fix: the only safe reversal is the contrapositive.
2. **Assuming the inverse** ("Not delayed, so no email"). Fix: when the condition is false, the rule says nothing.
3. **Reversing "only if".** "A only if B" is "if A then B", not "if B then A".
4. **Thinking a rule is broken when its condition is false.** A rule is broken only by a case where the condition is true and the result is false.
5. **Swapping without negating (or negating without swapping) and calling it the contrapositive.** The contrapositive needs both: swap and negate both parts.

## Recap

1. "If p then q" is broken in exactly one case: p true and q false (a counterexample).
2. The original rule and its contrapositive (swap and negate both) always mean the same.
3. The converse (swap only) and the inverse (negate only) are not equivalent to the original.
4. "A only if B" means "if A then B"; "A unless B" means "if not B then A".
5. "p if and only if q" works both ways and is true exactly when p and q are both true or both false.
